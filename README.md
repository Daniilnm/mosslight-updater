# Mosslight

## Текущий выпуск — 1.1.1 / v24

Кнопка **«Обновить Mosslight»** всегда видна в отдельном блоке с версией программы. Она проверяет и устанавливает обновление без выбранной папки и независимо от обновления игровых файлов. Если обновлений нет, программа сообщает, что установлена последняя версия.

Самообновление заменяет `Mosslight.Update.exe` по прежнему пути. Старый EXE нужен только до подтверждения запуска нового окна; после успешного запуска `Mosslight.Update.previous.exe` удаляется. При неудаче прежний EXE восстанавливается. Удаление после успешного обновления работает и при переходе с помощника 1.1.0.

Сборка v24: **408 модов / 693 файла**, добавлены Ars Elemental 0.7.10.4 и клиентский Ars Mana HUD 1.0.1 (числовая мана). Mana Meter по исходной ссылке рассчитан на 1.20.1 / Forge и в нашу сборку не включён. Источники новых JAR — официальный CDN CurseForge, закреплённый в `download-sources-v24.json`. `install-channel.json`: pack-v24 / app-v1.1.1; совместимый `channel.json`: pack-v22 / app-v1.1.1.

Проверки этого выпуска: 26 сценариев ядра, 4 сценария интерфейса, успешная замена и аварийный возврат с новым и прежним помощником; v22→v24 с полным откатом. Для повторения сценариев прежнего помощника: `test.ps1 -LegacyHelperPath <старый-тестовый-EXE>`.

Ниже — история первой установки 1.1.0.

## Первая установка и обновление — 1.1.0

Mosslight 1.1.0 устанавливает весь комплект в пустую папку `mods` и затем скачивает только изменения. В своём лаунчере заранее создайте отдельный профиль **Minecraft 1.21.1 / NeoForge 21.1.259**, закройте игру, выберите папку профиля (например `.minecraft/versions/4`) и нажмите **«Установить сборку»**. Minecraft, Java и загрузчик устанавливает лаунчер.

Каталог v23 содержит те же игровые файлы, что v22: 406 модов и всего 691 файл. Сервер остаётся совместимым. Полная загрузка — примерно 1,09 ГБ; первый запуск игры проверяется отдельно пользователем. Сторонние моды скачиваются с официальных CDN Modrinth/CurseForge и проверяются по SHA-256. Наши файлы и точечно разрешённые JAR скачиваются из GitHub Releases. При обрыве можно повторить установку; завершённые файлы берутся из кэша. Восстановление из полного ZIP остаётся дополнительной возможностью.

У существующей 1.0.0 с сохранённой папкой нажмите «Проверить» → **«Обновить программу»**: EXE заменится встроенным помощником. Отдельно вручную скачивать новую программу не требуется. Если 1.0.0 ещё ни разу не приняла папку, её ошибка не даёт открыть самообновление; [однократное сохранение папки](LEGACY-UPDATE-RU.md) открывает кнопку без скачивания нового EXE.

В 1.1.0 проверка обновления программы выполняется при старте даже без папки и независимо от ошибок каталога сборки.

Каналы выпуска: `stable/channel.json` оставлен совместимым с 1.0.0 (pack-v22 / app-v1.1.0); начиная с 1.1.0 используется подписанный `stable/install-channel.json` (pack-v23 / app-v1.1.0). Старые pack/app Releases не изменяются.

Проверки: `test.ps1` проверяет ядро, интерфейс и замену EXE/автоматический возврат. `InstallTests` проверяет настоящую полную установку, SHA-256, сохранность личных файлов, полный откат и повторную установку без загрузок. `download-sources-v23.json` закрепляет точные источники сторонних JAR; `source-audit.py` повторно сверяет их с установленной эталонной сборкой и скачивает проверочные копии отдельно от игры.

Ниже сохранено описание исходного выпуска 1.0.0 и его исторические ограничения.

Небольшой обновлятор нашей сборки Minecraft 1.21.1 / NeoForge. Работает отдельно от CurseForge и TLauncher: один раз выбирается папка сборки, затем достаточно нажать **«Обновить»**. Minecraft он не запускает и не закрывает.

## Состояние 15.10.2026

Mosslight — самостоятельный EXE для Windows x64. Скачайте [Mosslight.Update.exe](https://github.com/Daniilnm/mosslight-updater/releases/download/app-v1.0.0/Mosslight.Update.exe), сохраните в удобную папку и запустите. Отдельная установка .NET не нужна. Один раз выберите клиентскую папку сборки с `mods`, закройте Minecraft и нажмите **«Обновить»**.

Актуальная игровая сборка — **v21**, с нативным интерфейсом рюкзака `.2`. Сервер и клиенты используют один протокол `bmc5-2`; старая `.1` несовместима. У рюкзака одна кнопка, штатные вкладки и верстак только от установленных улучшений. Shift переносит предметы между открытым рюкзаком и сундуком, при закрытом рюкзаке — между инвентарём и сундуком. Сам форк собран и проверен вне игры; визуальная и сетевая игровая проверка ещё нужна.

## Что сделано

- Сравнивается весь каталог последнего выпуска, поэтому можно пропускать версии. Скачиваются целиком только изменившиеся файлы, с gzip и продолжением оборванной загрузки.
- Старые файлы из учёта обновлятора и известных прошлых архивов автоматически удаляются через резервную копию. Дополнительные личные моды сохраняются; совпадение modId предлагает явно перенести конфликтующий мод в бэкап.
- SHA-256 проверяется после загрузки и установки. Каталог, канал и самообновление имеют RSA/SHA-256 подпись с закреплённым открытым ключом.
- Перед заменой всё скачивается и проверяется во временной папке, затем сохраняются оригиналы и журнал. Ошибка установки вызывает откат; после прерывания процесса восстановление продолжается при следующей проверке.
- Хранятся три завершённых бэкапа. Копии с обнаруженными личными правками автоматически не удаляются.
- В настройках есть **«Откатить последнее обновление»** и **«Указать полный архив»**. Архив используется только как источник файлов, подходящих по SHA-256, и не распаковывается поверх установки.
- **«Обновить программу»** скачивает подписанный EXE, запускает отдельный помощник и закрывает только обновлятор. После замены новая программа подтверждает открытие окна. При неудаче автоматически возвращается прежний EXE. Рядом остаётся `Mosslight.Update.previous.exe`.
- Никаких прав администратора, PowerShell-скриптов из сети, запуска Java или управления сервером. Встроенный PowerShell только читает список Java-процессов, чтобы не обновлять открытый клиент.

## Личные файлы

`options.txt`, миры, карты, скриншоты, серверы, resourcepacks и большинство конфигов не входят в управляемые пути. Jade создаётся только при отсутствии. В ImmediatelyFast меняется только `hud_batching=false`, в ModernFix — `mixin.perf.faster_item_rendering=false`, в клиентском Cold Sweat — `Preferences / Show Water Effect = 0`. Остальные значения сохраняются; при ручном откате сохраняются и внесённые позже личные правки.

Остальные пять конфигов из старого архива относятся к общему балансу и обновляются полностью. Управляемый перечень ограничен в `Core/Security.cs` и `Core/ConfigPatches.cs`. Серверные папки, выход за выбранную папку, ссылки и опасные имена отклоняются.

## GitHub Releases

Нужен публичный репозиторий выбранного владельцем аккаунта. Друзьям аккаунт GitHub не нужен.

- `pack-v21`: подписанный `pack.json` и новые `blob-<sha256>.gz`; неизменившиеся данные ссылаются на опубликованный `pack-v20`.
- `app-v1.0.0`: самостоятельный `Mosslight.Update.exe` и подписанный `app.json`.
- `stable`: маленький подписанный `channel.json`, указывающий на оба текущих выпуска.

Файлы версионных выпусков не перезаписываются. Следующий выпуск получает новый номер; неизменившиеся файлы ссылаются на старые Releases. Сначала публикуются полный выпуск сборки и программы, затем канал. Временная ошибка публикации канала не затрагивает установленную игру; повторный запуск публикации пропускает уже загруженные файлы с тем же SHA-256. Старые Releases сохранять для пропуска версий и восстановления.

Полный старый ZIP остаётся для первой установки поверх исходной BMC5 с правильным загрузчиком. Обновлятор не устанавливает Minecraft или NeoForge.

### Сторонние моды

Проверены метаданные фактических JAR: среди модов есть ARR и другие ограничительные лицензии. В GitHub-каталог включены хеши всех 691 файлов сборки, но размещаются только наши конфиги/KubeJS/квесты и собственные JAR, явно разрешённые по SHA-256 в `approved-jars.json`: `bmc5tweaks 1.0.12` и MIT-форк `backpack-side-gui .2` (историческая `.1` сохранена в v20).

404 сторонних JAR остаются в существующей установке. Если такой файл повреждён или отсутствует, потребуется указать имеющийся полный архив. Переходы **v17/v18/v19/v20 → v21 проверены: новых сторонних JAR для них скачивать не нужно**. При появлении нового стороннего JAR сборщик следующего выпуска остановится, пока его размещение не будет разрешено. Перенос файлов на GitHub не меняет их лицензий.

### Сборка владельцем

Нужен .NET SDK 10.0 и пакеты runtime Windows x64; друзьям .NET устанавливать не нужно. Репозиторий не содержит закрытого ключа или токенов.

```powershell
dotnet restore ReleaseTool/Mosslight.Update.ReleaseTool.csproj --configfile NuGet.Config
# Только если ключ ещё не создан. Существующий ключ сохранять для следующих выпусков.
dotnet run --project ReleaseTool/Mosslight.Update.ReleaseTool.csproj --no-restore -- keygen .private

./build-release.ps1 -Repository 'OWNER/mosslight-updater' `
  -PrivateKey '.private/release-private.pem' `
  -Archive 'ПОЛНЫЙ_ПУТЬ/BMC5-mods-2026-10-15-v21.zip' `
  -LegacyArchiveFolder 'ПАПКА_СО_СТАРЫМИ_АРХИВАМИ'
```

`OWNER` сейчас `Daniilnm`. Внимание: этот скрипт пересобирает EXE; для изменения только сборки с сохранением app 1.0.0 использовать раздел обычного выпуска в RELEASING-RU.md. Повторная сборка EXE требует нового AppVersion. Для следующего выпуска передать `-PackVersion`, `-AppVersion`, новый ZIP и `-PreviousPack` с подписанным предыдущим каталогом. Изменить заметки выпуска в параметре `Notes`, а новые собственные/разрешённые JAR внести по точному SHA-256 в `approved-jars.json`. Любой новый запуск сборки использует новую пустую папку `-Output`.

Сохранить закрытый ключ отдельно в надёжной копии: потеря ключа потребует вручную раздать новый доверенный EXE. При компрометации ключа также нужна ручная замена доверия.

Для публикации в уже созданный репозиторий инструмент принимает `GH_TOKEN` из окружения: fine-grained token с `Contents: write` только к выбранному репозиторию. Токен не передавать в командной строке и не сохранять в JSON. Подключение GitHub в Codex и `GH_TOKEN` для локального CLI — разные способы доступа; подключённый коннектор не означает, что локальная переменная уже задана.

```powershell
dotnet run --project ReleaseTool/Mosslight.Update.ReleaseTool.csproj --no-restore -- `
  publish artifacts/release 'OWNER/mosslight-updater' .private/release-public.pem
```

Для следующего выпуска используйте тот же ключ. Коннектор GitHub не передаёт свой токен в локальный CLI; при отсутствии `GH_TOKEN` можно опубликовать подготовленные файлы через GitHub Releases в браузере. Код репозитория публикуется через коннектор; браузер нужен для операций создания репозитория и загрузки вложений Releases, которых в доступных командах коннектора нет.

## Проверки

```powershell
dotnet restore Tests/Mosslight.Update.Tests.csproj --configfile NuGet.Config
dotnet run --project Tests/Mosslight.Update.Tests.csproj --no-restore -- test-results
```

`SelfUpdateTests` — самостоятельный процесс для тестов настоящей замены EXE 1.0.0 → 1.0.1 и неудачного запуска. `ArchiveTests` — проверка настоящих старых архивов в отдельных папках, с побайтовой проверкой отката по SHA-256. Эти тесты не запускают игру.

Фон создан встроенной генерацией, включён в `App/Assets/hero.png`. Промпт и сведения о дизайне — `DESIGN.md`.
